# 분석 과정

## 1. 분석 자료

자료는 한국교통안전공단의 국내 철도사고 및 운행장애 발생 정보(2024년 12월 31일 기준)에서 가져왔다. 사고 종류가 `장애(지연)` 또는 `장애(무정차)`인 754건을 먼저 골랐다. 여섯 개 군집분석 변수에 결측이 없는 사례만 남겨 최종 분석 자료는 739건이 되었다.

군집분석에 사용한 변수는 다음과 같다.

- 철도구분
- 열차종류
- 지연운행 현황
- 지연운행 원인
- 근본원인별 원인
- 장소유형A

표본이 매우 적은 일부 범주는 분석 전에 묶었다. 열차종류의 입환차량·혼합열차·시운전열차·작업차량·회송열차·기타는 `기타열차`로 통합했다. 장소유형A의 역 대합실과 역 작업장은 `역(기타)`로, 열차 내·기타·차량기지·운행선은 `기타장소`로 묶었다. 지연운행 현황의 열차분리·선로장애·규정위반도 `기타(소수)` 범주로 합쳤다.

각 사례에는 `case_id`를 부여했다. 군집분석 입력, 피해·지연 조회표, 군집 결과는 이 식별자로만 연결한다. 세 파일 모두 식별자 중복과 누락이 없는지 코드에서 확인한다.

## 2. clusCA 군집분석

범주형 자료의 군집과 저차원 좌표를 함께 추정하는 clusCA를 사용했다. 최종 모형의 설정은 아래와 같다.

| 항목 | 설정 |
|---|---:|
| 군집 수 | 6 |
| 차원 수 | 5 |
| 선택 기준 | 평균 실루엣 폭(`asw`) |
| 초기값 반복 | 100회 |
| 난수 시드 | 1234 |

R 코드는 [`analysis/fit_clusca.R`](../analysis/fit_clusca.R)에 있다. 실행 결과는 `case_id`와 군집 번호 두 열로 저장한다. 현재 공개한 결과의 군집별 사례 수는 337, 132, 97, 90, 48, 35건이다.

## 3. 군집 특성 확인

군집 번호와 여섯 범주형 변수의 분할표를 만든 뒤 카이제곱 독립성 검정을 시행했다. 변수별 연관성 크기는 Cramér's V로 비교했다. 어떤 범주가 특정 군집에서 많이 또는 적게 나타나는지는 Haberman 조정 표준화 잔차로 판단했다. `ASR ≥ 1.96`은 기대도수보다 유의하게 많이 관찰된 범주, `ASR ≤ -1.96`은 적게 관찰된 범주로 해석했다.

[`analysis/cluster_profiles.py`](../analysis/cluster_profiles.py)는 원자료에서 분할표를 다시 만들고 다음 파일을 생성한다.

- `results/cluster-profiles/chi_square_summary.csv`
- `results/cluster-profiles/adjusted_residuals.csv`
- `results/cluster-profiles/selected_characteristics.csv`

희소 범주가 있는 변수는 기대도수 5 미만 셀이 포함된다. 특히 `근본원인별 원인`은 세부 범주가 많으므로, 카이제곱 유의확률만으로 군집명을 정하지 않고 효과크기와 ASR, 실제 도수를 함께 확인했다.

## 4. 피해와 지연 지표

피해액은 두 가지로 나누어 보았다. 먼저 군집별로 피해액이 0보다 큰 사례의 비율을 계산했고, 그다음 피해액이 발생한 사례만 남겨 중앙값을 구했다. 지연열차 수와 최대 지연시간은 결측을 제외한 중앙값을 사용했다. 평균보다 중앙값을 택한 이유는 세 지표 모두 일부 큰 값의 영향을 강하게 받기 때문이다.

계산 코드는 [`analysis/impact_summary.py`](../analysis/impact_summary.py), 결과는 `results/impact_summary.csv`에 있다.

## 5. 연관규칙 분석

연관규칙은 전체 자료를 한꺼번에 분석하지 않고 각 군집 안에서 따로 계산했다. 한 사례를 하나의 트랜잭션으로 보고 `변수명=범주명` 형식의 항목 여섯 개를 부여했다. 서로 다른 변수에 같은 범주명이 있어도 구분되도록 변수명을 항목에 포함했다.

| 기준 | 값 |
|---|---:|
| 최소 지지도 | 0.20 |
| 최소 신뢰도 | 0.60 |
| 최소 향상도 | 1.20 |
| 최대 항목집합 길이 | 3 |

Apriori로 빈발항목집합을 찾고, 같은 변수가 선행부와 후행부에 동시에 들어간 규칙은 제외했다. 이 기준에서 군집별 후보 규칙 수는 0, 20, 31, 3, 60, 26개였다. 후보는 향상도, 신뢰도, 지지도 순으로 정렬했다. 규칙이 존재하는 군집에서 상위 3개씩 골라 논문 표의 15개 규칙을 만들었다.

제공된 [`notebooks/association_rules.ipynb`](../notebooks/association_rules.ipynb)의 계산을 [`analysis/association_rules.py`](../analysis/association_rules.py)로 옮겼다. 노트북에 들어 있던 개인 PC 절대경로는 제거하고 저장소 상대경로를 사용했다. 스크립트를 실행하면 다음 세 파일을 다시 만든다.

- `results/association-rules/association_rule_summary.csv`
- `results/association-rules/table5_association_rules_candidate.csv`
- `results/association-rules/table5_association_rules.csv`

## 6. 검증 범위

회귀 테스트는 최종 15개 규칙, 여섯 변수의 Cramér's V, 군집별 피해·지연 요약이 공개 결과와 일치하는지 확인한다. `python -m pytest -q`로 실행할 수 있다. clusCA 재추정은 R 실행 환경과 `clustrd`가 필요하므로 Python 테스트에는 포함하지 않았다.
